# Contributing to BrainStorm

Thanks for helping out. The short version:

1. Create a branch from `main` (`feature/short-name` or `fix/short-name`).
2. Keep changes small and focused.
3. Open a pull request. CI must be green before merging.
4. Ask for a review; squash-merge when approved.

Commit messages: short, in the imperative ("Add login screen", "Fix balance rounding").

Never commit secrets (tokens, keys, `.env` files). If you did by accident, tell the team right away so the secret can be rotated.
